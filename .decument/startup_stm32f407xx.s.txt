starup파일은 STM32에서 사실상 전원은 인가 시 가장 먼저 실행된다. 실행순서는 대략
1. 전원인가
2. vector table (자동으로 sp와pc를 설정한다.)
3. startup_stm32f407zgtx.s
    4. Reset_Handler
    5. SystemInit()
    6. .data 복사 / .bss 초기화
7. main()

.으로 시작하는 어셈블러 지시어(또는 pseudo-op)는 어셈블러를 설정하는 문구들이다.

<27~>
.syntax unified : ARM Unified Assembly 문법 사용
.cpu cortex-m4 : 이 코드는 Cortex-M4용이다
.fpu softvfp : 부동소수점 처리 방식 지정
.thumb : Thumb 명령어 집합 사용, Cortex-M계얼은 전부 Thumb모드로 동작한다.

.global ~ : 이 심볼을 외부에 공개 
.section .text.~ : 다음 코드를 .text 섹션에 넣어라
이처럼 세부 섹션으로 나누어 생성된다.

.weak ~ : 약한 심볼(Weak Symbol)로 선언한다.
즉 동일한 함수명을 가진 함수가 기본적으로 존재하는데, 동일함수명을 사용자가 정의하면 그것을 우선으로 사용한다는 의미이다.

.type ~, % : ~는 %~타입의 심볼이다.
함수/데이터/변수 타입을 정의하여 어셈블러에게 알려준다.

.word : 4바이트 데이터 저장

.b : 무조건 점프
.bl : 함수 호출, LR(Link Register)에 돌아올 주소를 저장하고, PC에 호출된 함수 주소가 저장된다.
.bx : 호출된 함수의 마지막에 선언되면 LR에 저장된 주소로 복귀한다.
.bcc : Branch if Carry Clear

.thumb_set : 앞과 뒤의 주소를 같게 한다.

57~102는 reset handler의 동작이다. STM32의 전원이 켜진후 main함수가 실행되기 전까지 진행된다.
<60~61>
SP에 estack주소를 저장한다. stack은 RAM의 맨 끝에서부터 시작하기 떄문이다.  Reset_Handler가 실행되자마자 스택 사용준비를 한다.

<64>
위에서 설명했듯이 SystemInit을 호출한후 다시 돌아와 LoopCopyDataInit을 실행한다.

<67~81>
LoopCopyDataInit에서 조건을 검사하고, 조건을 통과하면 CopyDataInit을 실행한 후 다시 LoopCopyDataInit을 반복한다.
Flash에 저장된 .data초기값들을 4바이트씩 읽어 RAM의.data영역으로 복사하는 과정이다.
ldr r4, [r2, r3] : FLASH메모리 주소에 접근해 데이터를 r4에 저장
str r4, [r0, r3] : r4의 데이터를 RAM메모리 주소에 접근해 저장

<83~95>
RAM의 .bss영역을 전부 0으로 채운다.

<98~102>
startup과정의 마지막 단계. main프로그램으로 넘어가는 과정이다.
__libc_init_array함수는 c/c++ 런타임 초기화와 관련된 함수이다. main()이 실행되기 전에 object생성자 실행 또는 라이브러리 초기화함수들을 호출한다.
이후 main()을 호출한다. main함수가 종료되면 bl의 로직대로 다시 이곳으로 돌아오는데, 보통 while(1)이 있기에 그렇지 않다.

<111~115>
Default_Handler는 기본 예외/인터럽트 처리 함수이다. 예외/인터럽트가 발생하면 main에서 벗어나 인터럽트 핸들러를 실행하게 한다. 인터럽트가 처리되면 다시 main으로 복귀한다.
만약 인터럽트를 활성화했으나 핸들러가 구현되지 않으면, 
b_Infinite_Loop를 계속 실행하게 된다.

<123~231>
g_pfnVectors는 FLASH에 배치되는 vector table이다. 각 인터럽트/예외에 대응하는 handler의 주소를 저장한다.

<240~508>
만약 사용하자 해당 handler를 따로 구현하지 않으면, 해당 Handler의 주소는 Default_Handler의 주소가 되어 실행되도록 한다.
즉 해당 인터럽트 함수 이름을 제공하되, 기본적으로는 Default_Handler와 같은 주소를 사용하도록 한다. 하지만 다른곳에서 해당 인터럽트를 정의했다면 그것을 사용하도록 하는 로직이다.
이 명령어들에 따라 벡터테이블의 주소데이터는 빌드과정에서 결정된다.
