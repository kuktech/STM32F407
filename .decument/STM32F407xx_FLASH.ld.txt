.ld는  Linker Script파일이다. 컴파일은 .c -> 컴파일 -> .o -> 링크 -> elf -> bin순서로 진행되는데,여기서 Linker는 
1.변수를 저장할 RAM의 위치 
2.함수를 저장할 FLASH의 위치 
3.stack과 heap의 할당공간 
4.각 메모리배치 
그 규칙을 저장한 파일이 ld파일이다.

FLASH.ld는 프로그램을 Flash에 다운로드함을 의미하며 일반적인 사용방법이다. 

<53>
전원인가 시 Reset_Handler부터 실행한다. 해당 프로그램은 Starup 파일에 있다.

<56~61>
시작주소, 크기를 정의하고 있다.

<67~68>
stack과 heap의 저장용량이 정의되어 있다. 

그 아래부터는 각 section블록들을 정의한다. .program code로 시작하여 >FLASH로 끝나는 방식으로 
프로그램의 저장공간을 지정한다.
반대로 .data로 시작하여 >RAM으로 끝나는 방식으로
초기화된 전역변수를 저장한다. 

<74~79>
인터럽트 벡터 테이블을 저장한다. FLASH 맨 위에 위치한다.

<82~96>
모든 함수코드를 저장한다. 컴파일 시 기계어가  .text영역으로 들어간다.

<99~105>
읽기전용 데이터를 저장한다. ex) const char msg[] = "Hello";

<175~185>
초기값 있는 전역변수가 저장된다. >RAM AT>FLASH는 초기값을 FLASH에 저장하여 휘발성인 RAM때문에 값이 소멸되지 않게 한다. Startup코드가 실행되면서 FLASH의 데이터를 RAM에 복사한다.
변수값이 변경되어도 RAM데이터만 변경되고 FLASH는 유지된다.
>RAM : 실행위치(VMA,CPU가 실제 사용하는주소)
AT>FLASH : 초기값 저장위치(LMA,초기 데이터가 저장된 주소)

<233~243>
BSS영역에는 초기값 없는 변수가 저장되는 영역이다. 부팅 시 자동으로 0으로 초기화되고 RAM사용량 대부분이 여기에 소모된다.

<249~258>
Heap/Stack영역이다. RAM마지막 공간에 할당된다.

RAM
┌──────────┐
│ .data    │
├──────────┤
│ .bss     │
├──────────┤
│ Heap     │
├──────────┤
│          │
│ 여유공간 │
│          │
├──────────┤
│ Stack    │
└──────────┘


+ *(.data) : *는 모든 오브젝트 파일에 정의된 .data섹션을 가져오는 명령어이다. 즉 컴파일 시 각 파일에 있는 변수가. data섹션으로 들어간다.
*(.data*) : .data로 시작하는 내부 섹션들을 전부 포함한다.

PROVIDE는 링크스크립트(.ld)에서 사용하는 특별한 명령이다. 
PROVIDE(_end =.); 또는  PROVIDE(end = .); 이것은 만약 이 심볼이 정의되어 있지 않았다면, 여기서 정의한다는 뜻이다.
다른 코드에서 같은 이름의 변수가 정의되면 충돌이 발생하기에 먼저 확인하기 위해 사용된다.

링커스크립트에서 .은 현재주소를 의미한다. 정리하면 모든 섹션을 다 모든 뒤 현재주소,즉 끝 주소인 .을 PROVIDE를 이용해 현재주소에 이름을 붙이는 것이다.

<STM32에서 자주 사용되는 주소심볼>
_etext : FLASH에 저장된 코드영역의 끝 주소
_sdata : RAM의 .data 시작주소
_edata : RAM의 .data 끝 주소
_sbss : .bss의 시작주소
_ebss : .bss의 끝 주소
