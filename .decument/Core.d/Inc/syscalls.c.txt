이곳엔 실제 애플리케이션 로직은 없다. C표쥰 라이브러리(printf,scanf 등)와 STM32하드웨어를 연결해주는 중간 다리 역할을 한다.
PC에서 printf문을 쓴다면 운영체제가 콘솔 창에 출력해준다.그러나 STM32는 운영체제,모니터,키보드가 없다. STM32는 printf를 어디에 출력하는지, scanf를 어디서 입력받는지 모른다. 따라서 printf는 UART로 전송하도록, scanf는 UART로 입력받도록 알려주는 역할을 본 파일이 한다. 
운영체제가 없는 환경에서 필요한 시스템 호출들을 최소한으로 구현한 파일이다.

아래 함수들은 STM32에서는 지원하지 않는 기능들이다.
_open : 파일 시스템 없기에 fopen()은 지원하지 않는다.
_close : 파일 닫기 불가
_fork : 리눅스의 프로세스 복제기능
_execve : 프로그램 실행
_wait : 프로세스 대기
_kill : 프로세스 종료
_getpid : 프로세스ID

+ 1.컴파일 : printf를 호출하는 코드를 생성, 아직 _write()는 찾지 않는다.
2. 링크 : 모든 목적 파일(.o)를 모아두고 printf가 필요함을 발견 후 라이브러리를 확인, 라이브러리의 printf구현을 가져온다.
3. printf 내부에서 _write가 필요하다는 또 다른 심볼을 발견한다. 따라서 링커는 프로젝트 전체를 확인하여 _write는 찾는다.
